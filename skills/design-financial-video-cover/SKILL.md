# 制作财经双画幅封面

遵循“内容承诺 → 封面策略 → 自动选材 → 图生图 → 双画幅重构 → 检查与保存”的顺序。不要让用户挑选或确认搜索素材，不要在页面展示搜索原图、候选列表、来源卡片或评分。

## 1. 从内容确定承诺

必须先读取 [references/placement-policy.md](references/placement-policy.md)，它是场景判断与点击选择的共同规则，包装和生成前文案确认也使用同一文件。默认跨平台共用、标题是否可见不确定，按独立封面设计；标题同屏时互补只是可选策略，不是通用硬要求。目标是有效点击，主体、事实、安全区与可读性保证承诺能被识别和兑现。

读取当前选题、事件主体、标题、Hook、核心矛盾、研究证据和市场方向。先确定：

- 观众在 0.5 秒内必须认出的对象；
- 想触发的唯一情绪：危险、机会或旧共识被打破；
- 封面故意留下、必须点击才能补齐的信息缺口；
- 准确主体名，以及正文能够兑现、优先4—8字的钩子；二者组成完整封面文案。

封面必须脱离标题独立成立：抖音主页与历史作品网格可能不展示标题，观众仅看封面也必须认出讲谁、讲什么。公司题写准确公司简称，人物题写人名，资产题写资产名；行业或政策题写具体对象。主体识别与事实准确是底线，在此基础上选择最有点击动机的文案。允许重复标题中的主体、数字或提问，不能为了互补而弱化吸引力，不承诺无依据结论。

### 点击动机优先

封面的目标是让人立刻知道主体，并产生一个具体、值得点开求解的问题。美观、短字数、与标题互补都是手段，不得压过点击理由。

选文案时，在内部比较：标题里最强的具体提问（尤其后半句）、这个提问的短口语版本、独立重写的一句。按原有信息比较，不发明事实；只交付最强的一版，不向用户增加选择步骤。标题提问已经短、具体、反常且正文能回答，就直接采用并补主体名，不强行原创另一句。

优先保留可感知的预期差、数字冲突或利益分歧，让观众能说出“我想知道为什么”。不要把好问题压成新闻摘要、抽象口号、任务目录或不顺口的电报体。“看这四件事”“估值重构”“散户怕机构要”等缺少具体问题或难以照读的文案应重写。不是每期都要问句，有证据且更有吸引力的直接判断同样可用。

标题中的绝对化措辞也要审：有机构认购不能写“没人要”，资金流出不能自动写“逃命”；疑问号不能掩盖虚假前提。提问必须可由正文回答，不能靠买卖暗示、收益承诺或夸大风险吸引点击。

缩成主页三列网格后检查：主体能否识别、问题能否一遍读懂、为何要点是否具体。放不下先删背景修饰、保留关键数字和疑问，再调整排版；不为凑4—8字损失意思。没有同口径曝光和点击数据时，这只是点击潜力的编辑判断，不得宣称已验证CTR提高。

## 2. 认领封面类型

只选择一种结构：

- 问题、风险和事件解谜题：使用“氛围纪录型、主体主导”。真实主视觉是第一落点，主锤字是第二落点。
- 清晰判断和机制结论题：使用“财经周刊型、大字主导”。主锤字是第一落点，真实主视觉退为次一级证据符号。

禁止让大字、人物、图表和多个物件同时争夺第一落点。第二元素只有在直接构成矛盾时才允许出现。

### 人物准入门

人物不是禁用元素，但必须具有明确身份和不可替代的信息价值。生成前先判断：

1. 当前事件是否明确指向一位具名真实人物；
2. 该人物的行动、表态或身份是否就是事件因果链的核心，而不只是新闻配图里的出席者；
3. 原始证据和真实参考图能否共同核验人物身份。

三项全部成立，才允许使用人物，例如特朗普宣布关税、鲍威尔发表利率立场或某位公司负责人发布关键指引。人物必须是观众能够识别的那位具名真人，承担“谁采取了行动”的信息，不得只是装饰。

任一项不成立，就使用非人物视觉锤。禁止生成没有姓名、没有事件角色、无法核验身份的 AI 假人，包括陌生面孔、商务人士、交易员剪影、背影、群众、人偶、微缩小人、雕塑人像、假人模特、手和类人轮廓。一个“看起来像金融人士”的人不构成信息。

## 3. 固定系列审美基因

保持“高压财经调查纪录片 × 国际商业周刊封面”的系列语言：

- 石墨黑至深海军蓝的低饱和底色；
- 硬切电影级定向光、真实纸张或金属颗粒、锐利边缘和高明暗反差；
- 紧凑、有压迫感的中文黑体和明确负空间；
- 每期只使用一种信号色：风险用警报红，机会用克制金，疑问用冷白；
- 每期只更换主视觉和主锤字，构图逻辑、材质、字体气质和色彩纪律保持一致。

避免廉价新闻海报、通用 AI 科技蓝、塑料高光、全屏霓虹、金币雨、牛熊雕像、赛博界面、密集 K 线、多图拼贴、账号名、Logo、角标和水印。

## 4. 自动搜索并选择主题素材

必须先搜索素材再做图生图，不以纯文生图冒充完整流程。

1. 从选题提取最能代表主题的实体、动作和场景，用“选题主体 + 视觉锤 + 高清新闻图”形成图片查询。
2. 通过百度 WebSearch 图片模态召回大图和横图；不要扩大每日新闻扫描，也不要把搜索素材写入页面。
3. 对候选执行自动评分：
   - 主题词、实体和动作命中越多，分数越高；
   - 官方、主流财经媒体或当事机构来源加分；
   - 百万像素、适合重新构图的横图和清晰主体加分；
   - Logo、图标、GIF、图库、水印、二维码、广告、缩略图和低清图降权或淘汰。
   - 先执行人物准入门。人物主题只保留具名人物的可核验真实照片；非人物主题淘汰人物、人像、演讲、会见、发布会、交易员、剪影、人偶和微缩模型素材。
4. 对高分候选逐一验证 HTTPS 地址、图片类型和可下载性，选择首张通过验证的素材。
5. 没有可信的具名实体图时，继续搜索与主题直接相关的泛化真实场景，例如芯片晶圆、交易大厅、港口、油井或数据中心；不要选择不相关的漂亮图片。
6. 找不到任何合格素材时明确失败并停止，不悄悄切换纯文生图。

自动选择不等于放弃安全：禁止地图；涉及台湾、香港、澳门、新疆或西藏的封面禁止旗帜、国徽和任何人物。不得选择可能造成具名人物、设备型号或事件现场张冠李戴的素材。

## 5. 用参考图完成图生图

把选中的真实素材作为事实主视觉传给图片模型。要求保留主体可识别特征和硬边缘，但重新设计光线、背景、景深、色彩、文字与构图；禁止仅给原图套滤镜，也禁止让主体溶进氛围背景。

根据人物准入结果分支执行：

- 具名人物主题：明确写出唯一允许出现的人名，只保留参考图中该人物的可识别身份；禁止换脸、生成替身、增加随从、群众或第二个人。
- 非人物主题：提示词必须明确要求零人形。参考素材若意外含有人物，彻底删除人物，不得因“保留参考图主体”而保留陌生人；只提取相关的非人物实体、环境、材质或市场张力。

提示词必须包含：当期标题供理解、选出的最强封面提问或判断、主体名、核心矛盾、封面类型、唯一视觉锤、固定审美基因、单一信号色、完整逐字文字、禁止元素、目标画幅与安全区。允许标题中的强提问直接成为封面文案。

图中文字由“准确主体名＋本期钩子”组成，作为一个排版组，最多两行。主体名可以单独占一行，也可自然融入钩子；钩子优先4—8字，但不能为了凑字数删主体。总字数以能识别、能读清为准，通常6—16字，长主体使用观众认识且不混淆的简称。主体名是明显可读的正文文字，不是角标、Logo或小字标签；不能用照片、建筑或模糊标志代替主体名。完整文案在提示词中逐字指定，不额外添加其他宣传文字。若旧项目主锤字缺主体，生成时必须依据当前选题和确认包装补入准确主体名，禁止沿用其他项目主体。

## 6. 分别重构两个画幅

使用同一参考素材生成两次，禁止先生成一张再裁切另一张。

- 横版固定使用 4:3。四边各留至少 12%，把全部文字、主体完整轮廓和关键识别特征收进中央 76% × 76% 安全框。采用不对称三七构图，视觉锤约占六成，文字负空间约占四成；文字块宽度不超过画面 38%。
- 竖版固定使用 3:4。安全框左边界为 16%、右边界为 78%、顶部为 16%、底部为 74%；右侧 22% 和底部 26% 避让平台按钮、字幕与标题栏。采用“上方钩子—中部唯一重心—下方留空”的纵向视线瀑布，文字块宽度不超过画面 62%、高度不超过 20%。

背景、光影和纹理可以满版出血，但有意义的信息不得越过安全框。禁止文字笔画、头部、手部、产品边缘或主体关键部件贴边、出血、越界或被画布截断。平台从四边轻微裁切后，主视觉和主锤字仍必须完整。

两个画幅必须共享主锤字、参考主体、字体气质、材质与色彩纪律，但允许改变主体位置、景别、光线方向和负空间位置。

## 7. 检查、保存与失败处理

生成后逐张检查：

1. 主体名与钩子逐字正确、笔画完整；遮住视频标题，仅凭封面仍能说出本期主体，主体名缺失则该画幅不合格；
2. 缩小到手机信息流后仍能认出话题、情绪和唯一第一落点；
3. 主体身份与参考素材一致；具名人物主题只出现获准的那位真人，非人物主题不存在任何人物、假人、人偶、剪影或类人轮廓；
4. 横版主体未截断，竖版文字未进入顶部、底部或右侧操作区；
5. 主体与点击理由同时清楚，标题中的强提问未被弱文案替换，正文能兑现承诺；不以是否重复标题作为不合格理由；
6. 不含地图、旗帜、国徽、平台界面、Logo、角标或水印。

只重新生成失败的画幅，保留已经合格的另一张。把横版、竖版、主锤字、提示词、选材查询、素材 URL、来源页面、站点、评分、搜索请求 ID 和生成时间写入同一个项目记录；前台只展示最终两张成品与下载按钮。

## 本项目实现

- 自动选材接口：`app/api/cover-material/route.ts`
- 安全图片代理：`app/api/image-source/route.ts`
- 双画幅工作流与项目保存：`app/creator-workflow.tsx`
- Poe 参考图生成：`scripts/poe_image.py`

修改实现时保持以上四处的数据字段和失败语义一致。
